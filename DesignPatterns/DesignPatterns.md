# 🎶 Notes to remember :
- Identify the aspects of your application that vary and separate them from what stays the same.
- Program to an interface, not an implementation
- Favor composition over inheritance
- Strive for loosely coupled designs between objects that interact.

# 🖥 DESIGN PATTERNS:
- **Strategy Design Pattern**: Encapsulate a set of algorithms into it's own classes so that they can be variably used according to the situation.
- **Observer Design Pattern**: The Observer Pattern defines a one-to-many dependency between objects so that when one object changes state, all of its dependents are notified and updated automatically.  Problems in  using the built in java Observer [[Observer Design Pattern]]
- **Decorator Design Pattern:** Classes should be open for extension, but closed for modification.
  But now that you know the Decorator Pattern, the I/O classes should make more sense since the java.io package is largely based on Decorator.
- **Factory Design Pattern:** 
	- **The Factory Method Pattern** defines an interface for creating an object, but lets subclasses decide which class to instantiate. Factory Method lets a class defer instantiation to subclasses.
	- **Abstract Factory Design**
